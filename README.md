# 《灰岩的案件手帳》Minimum Test

以「廣場的三點鐘」為案例的最小可玩 UI 原型，驗證場景調查、底部訊息展開、關鍵字調查與手帳紀錄是否直觀。手機直握優先，桌面自適應。

這是公開測試版，並非正式遊戲；畫面與敘事皆為測試素材。

## 直接試玩

[開啟公開試玩版](https://sora0811.github.io/Grey_index_test/)

使用手機或電腦瀏覽器開啟即可，無須下載、安裝或登入。兩案各自使用 LocalStorage 保存進度；選單可重置當前案件。也可下載原始檔後直接開啟 `index.html` 離線遊玩，請保留同一資料夾的 `app.js`。

## 測試方式

第一次請只交給受測者這句話：「調查廣場，取得一個新線索，再到手帳確認。」先不要提示點擊順序。

觀察：能否找到調查物件、注意底部新訊息、理解向上箭頭、找到關鍵字調查、確認手帳紀錄。記下猶豫的位置、誤點與需要提示的步驟。不要將完成速度視為唯一標準。

回饋請附上裝置／瀏覽器、畫面尺寸、卡住的步驟、原本預期的反應與實際結果；可在本 Repository 的 Issues 留下意見。截圖請避免包含個人資訊。

完成後可從選單「重新測試」。選單可切換物件標記，對比探索感與可發現性。提示依目前進度提供引導。

## 驗收路徑（觀察者用）

1. 點噴水池，底部單行訊息更新。
2. 點底部訊息或向上箭頭，向上展開描述。
3. 選「用關鍵字調查」，選「硬幣」。
4. 顯示「噴水孔」並自動記入手帳。
5. 打開手帳確認來源與調查關聯，返回廣場。

手機可測 390×844、360×640；桌面可測 1440×900。也支援手機橫握的左右配置。用實機測試時，請將資料夾放上靜態網站，或使用電腦的區域網路伺服器網址；手機的 localhost 並不會連到電腦。

## 給其他 AI 的評估題目

請實際操作原型，評估玩家是否能預測按鈕行為，底部訊息是否容易被忽略，手機點擊區是否足夠，以及手帳返回路徑是否清楚。請附上重現步驟與畫面尺寸，區分觀察結果與設計建議。

## 範圍與實作

純 HTML / CSS / JavaScript，SVG 為簡化場景示意。硬幣預先持有。鐘塔與路人有簡短調查回饋。敘事內容是測試文案，並非正式案件設定。第一案沒有完整結案、動畫、外部資源或資料上傳；兩案各自使用 LocalStorage 保存進度；選單可重置當前案件。桌面手帳為右側覆蓋面板，手機為全頁。

## 部署

GitHub Pages 從 `main` 分支根目錄發布。CSS 與 SVG 內嵌於 `index.html`，JavaScript 使用相對路徑 `app.js`，支援 `/Grey_index_test/` 子目錄部署。無須建置或額外依賴。


## 第二案 Prototype v0.1：商店街的生意經

[直接開始第二案](https://sora0811.github.io/Grey_index_test/street.html)。原案選單也有第二案入口，第二案選單可以返回原案。保留原案首頁與 Pages 設定，不需建置。

首次測試只告知：「商店街最近出現奇怪現象：麵包坊熱鬧，肉舖與酒坊卻抱怨生意變差。試著調查原因。」請勿先閱讀程式中的案件資料。可從任一店家、顧客或手推車開始；點對象後展開底部訊息，使用已有關鍵字交叉調查。

手帳分開呈現觀察／證詞與玩家推論，支持自由筆記、三段推論、部分理解結案及重新調查；不評分、不顯示完成比例、不要求查遍全部對象。原因選項在取得相關證詞前保留未知，結案不自動揭底。合理死路提供沒有新資訊的回應。

僅三店店面、街道、三名店員、兩名顧客與無主手推車；沒有後場、移動、時間推進或經濟模擬。簡短對話為原型測試文案，並非完整經濟設定。

存檔鍵：`greyrock.case01`、`greyrock.case02.v01`。來源（網域／通訊協定）不同的存檔不共用；本機測試進度不會帶到 Pages。不提供跨裝置同步；瀏覽器阻擋儲存時第二案會在手帳提示。第二案重置需在選單再次確認；兩案皆僅清除當前案件。

本機驗證與限制見 [TESTING.md](TESTING.md)。
